# LINK2REEL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refactor CUTLINE into a sourced URL-to-motion-video studio with deterministic 30–40 second vertical rendering.

**Architecture:** Add an isolated studio pipeline beside the legacy API while reusing SSE, media, download, and frontend primitives. Providers and deterministic fallbacks implement the same interfaces so offline demo and live Gemini production share one graph.

**Tech Stack:** FastAPI, LangGraph, google-genai 3.5, Playwright, DDGS, Pydantic, BeautifulSoup, Pillow, FFmpeg, Next.js 16, TypeScript, Motion, Vitest, pytest.

**Spec:** `docs/superpowers/specs/2026-11-18-link2reel-design.md`

## Global Constraints

- Final video is 30–40 seconds, 1080×1920, 30fps, H.264 with narration and music.
- Hook begins within 2 seconds; visual states change every 2–3.5 seconds; ease-out 400ms and ease-in 200ms.
- `window.seekTo(t)` is the only animation clock. Generated HTML has no external scripts or network dependencies.
- TTS text is verbatim narration. Style is attached to `Part.speech_metadata`, never spoken.
- Preserve existing CUTLINE tests, SSE replay, media serving, and memory caps.
- No git commits or pushes unless separately requested.

## Review Focus

- Invalid/private/unsupported URLs receive a bounded 422 rather than browser/network hangs; Task 1 tests URL validation.
- Model or image failures produce deterministic visual/audio fallbacks; Task 2 tests provider config and fallback behavior.
- Generated HTML cannot access external resources and always exposes seekTo; Task 3 tests sanitization and choreography.
- Long narrated scenes cannot exceed 40 seconds or clip mid-word; Task 4 tests timing and captions.
- SSE reload and mobile layouts retain all output and sources; Task 5 browser tests replay and overflow.
